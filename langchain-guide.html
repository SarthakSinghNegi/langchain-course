01 / Overview

What We Built

A LangChain-powered summarizer that takes raw text and produces structured summaries using GPT-5.

📦

Project Setup

Python 3.11 project managed with uv — the blazing-fast package manager. Dependencies include langchain, langchain-openai, and python-dotenv.

🔒

Secrets Management

API keys live in a .env file, loaded at runtime with load_dotenv(). The file is gitignored so your keys never hit the repo.

🤖

AI Integration

Connected to OpenAI GPT-5 via LangChain's ChatOpenAI wrapper. Also explored local models with Ollama (Gemma, GPT-OSS).

📊

Observability

LangSmith traces every chain run automatically — zero code changes needed. Just set environment variables and monitoring is live.

main.py 
from dotenv import load_dotenv
from langchain_core.prompts import PromptTemplate
from langchain_openai import ChatOpenAI

load_dotenv()

def main():
    information = """Elon Reeve Musk... (bio text)"""

    summary_template = """
    given the information {information} about a person I want you to create:
    1. A short summary
    2. two interesting facts about them
    """

    summary_prompt_template = PromptTemplate(
        input_variables=["information"],
        template=summary_template,
    )

    llm = ChatOpenAI(model="gpt-5", temperature=0)
    chain = summary_prompt_template | llm
    response = chain.invoke({"information": information})
    print(response.content)

💡 The Pipe Operator |

The pipe | is LangChain Expression Language (LCEL). It connects components like an assembly line. Building the chain (template | llm) is laying the tracks. Calling .invoke() sends the train.

Build vs Run — Why Both?

chain = template | llm

Building the pipeline. No data flows. No API calls. You're connecting the pieces together like blueprints.

Analogy: Laying down train tracks

chain.invoke(data)

Running the pipeline. Data flows through each step. API calls happen. You get results back.

Analogy: Sending the train

What is a PromptTemplate?

A PromptTemplate is a reusable instruction sheet with blank slots. The {information} placeholder is like a blank field on a form — you fill it in at runtime with actual data.

Why not just use f-strings?

Safety: PromptTemplate catches misspelled or missing variables with clear errors.
Reusability: Same template, different data each time.
Integration: It's a first-class LangChain citizen that plugs into chains.

PromptTemplate

LangChain Expression Language (LCEL)

LCEL lets you snap building blocks together with the | pipe. Each block does one job and passes results to the next.

📝

2-Step Chain

prompt | llm

Template fills, then AI processes.

🔗

3-Step Chain

prompt | llm | parser

Add a parser to clean the output.

⚙️

Run It

chain.invoke(data)

Send data through the pipeline.

🏭 Assembly Line Analogy

Each | is a conveyor belt between factory machines. One machine's output becomes the next machine's input. The rule: each piece's output must match the next piece's expected input.

ChatOpenAI — The AI Brain

ChatOpenAI is LangChain's wrapper around OpenAI's chat models. It handles authentication, retries, and formatting so you don't have to.

Cloud vs Local

ChatOpenAI — sends data to OpenAI servers. Powerful but costs money.
ChatOllama — runs on your machine. Free and private, but needs local setup.

The Runnable Interface

Every LangChain component (prompts, LLMs, parsers) follows the same interface. Each one knows what input it expects and what output it produces.

PromptTemplate receives a dictionary

It looks at the keys in your dict ({"information": "..."}) and fills in matching {placeholders} in the template.

Input: dict → Output: filled prompt

ChatOpenAI receives a prompt

It takes the completed prompt, sends it to OpenAI's API, and returns the AI's response as a message object.

Input: prompt → Output: AI message

Each component auto-detects its role

You don't tell PromptTemplate to .format() — the Runnable interface does it automatically when data arrives via the pipe.

Self-aware components

The pipe connects outputs to inputs

The | operator wires each component's output as the next component's input. If types don't match, you get a clear error.

Type-safe connections

05 / LangSmith

Automatic Observability

Zero-code tracing that monitors every chain run behind the scenes.

How It Works (Magic Explained)

load_dotenv() loads env vars

LangSmith config enters the environment.

LangChain checks: is tracing enabled?

Reads LANGCHAIN_TRACING=true. If yes, background tracker turns on.

Tracker records everything silently

Prompts, responses, timing, tokens — all captured automatically.

Data sent to LangSmith dashboard

Uses your API key and endpoint to upload traces.

The Secret: get_env_var()

LangSmith accepts both LANGSMITH_ and LANGCHAIN_ prefixes. Here's the actual code:

langsmith/utils.py 
def get_env_var(
    name,
    namespaces=("LANGSMITH", "LANGCHAIN")
):
    # Checks LANGSMITH_ENDPOINT first
    # Falls back to LANGCHAIN_ENDPOINT
    for ns in namespaces:
        value = os.environ.get(
            f"{ns}_{name}"
        )
        if value:
            return value
Backward Compatibility

LangSmith was once part of LangChain, so old LANGCHAIN_ variables still work. New preferred prefix is LANGSMITH_.
